# Content family → platform → narrative

`/start` and `/format` begin a fresh selection. The current Telegram flow is:

**Content family → platform/subtype → style/angle → one of three narrative structures → topic.**

| Main family | Platform/subtype choices |
|---|---|
| Story · about 30 seconds | Instagram Story; TikTok Story |
| Carousel | Instagram Carousel; TikTok Photo Carousel; LinkedIn Carousel (document post) |
| Reel / short video | Instagram Reel; TikTok Video |
| LinkedIn | Post; Article |
| More formats | Instagram single-image Post, Instants, Live, Broadcast Channel |

Stories retain the five existing styles: entertaining, educational, everyday situation,
question to the audience, and answer to a supplied question. Other formats retain the
existing creative angle menu. The next menu offers three narratives specific to the
selected platform and format. Angle/style expresses intent; narrative expresses progression.
The selected narrative takes priority over conflicting optional angle/framework suggestions.
Story brevity and intent, native output sections, factual integrity and safety remain mandatory.
There is no universal hook / three points / CTA sequence. Native section labels are transport
fields; stages are not mandatory audience-facing headings or numbered tips.

## LinkedIn carousel meaning and sources

This feature writes page copy and accompanying text for an **organic document post**.
It does not create a PDF, upload media, run carousel ads or publish automatically.
LinkedIn documents are supported by [Upload and share documents](https://www.linkedin.com/help/linkedin/answer/a518909)
and [Document uploads FAQ](https://www.linkedin.com/help/linkedin/answer/a523054).
These sources establish document functionality, not our creative sequencing or engagement guarantees.
Our 4–12-page range and density checks are configurable-in-code editorial defaults, not LinkedIn limits.

The three-choice narratives below are editorial hypotheses, based on each format's character.

## State, compatibility and cost

- The menu registry and narrative registry live in `bot/content_choices.py`.
- `Brief.structure_id` is checked against the selected format before any AI call. The writer,
  reviewer and bounded revision engine receive the same choice. The reviewer treats narrative
  adherence as part of the mandatory `format_identity` gate, not a creative-score bonus.
- Family changes clear platform, angle, brief, structure and pending clarification. Scoped
  callbacks reject another platform's choices and prevent skipping menu steps. `/cancel`
  clears the conversation. Old format IDs remain recognized. Legacy format/angle buttons migrate to the platform
  chooser (or family menu if state is missing); they cannot skip platform/structure selection.
- `/brief reset` clears advanced settings while retaining the menu's selected narrative.
  `/format` or `/start` changes that selection. An explicit valid brief structure can replace it.
- Generation logs and `/version` include `structure_id`; reports separate structure cohorts.
  A narrative experiment may compare structures; other experiment types must match them.
- Authorization, quota checks, token/cost budgets and revision bounds remain in the same
  generation path. Menu clicks make zero AI calls. No publishing capability was added.
- The default successful pipeline remains analyst + writer + reviewer (three calls), or
  writer + reviewer when analysis is disabled. The narrative adds a small trusted prompt
  fragment and brief field, not another model stage. Real latency/token costs need live measurement.

## Workflow repair: platform-flow-v2

The November 9 recording shows a freshly sent `/start` receiving the old four-button menu
and the old welcome message. The PR #17 implementation on `main` produces five grouped
families, so the recording does not show that implementation responding. The live deployed
commit/entry point and any other pollers must be checked before choosing a deployment fix.

This follow-up adds five visible steps, selected-platform labels and Back buttons. Old
inline format/angle buttons now enter the new platform chooser rather than continuing the
legacy angle → topic shortcut. If a restart lost an old angle button's context, it opens the
family menu. Completed legacy generation contexts remain supported for compatibility.

`/version` reports `workflow=platform-flow-v2`, bot username, family and menu stage in addition
to commit/source/prompt fingerprints. Startup logs the same workflow and bot username after
Telegram initialization. `create_application` is shared by the production entry point and
registered-handler tests. Tests feed actual decoded Telegram updates into the real
Application dispatcher, with only the Bot API HTTP transport replaced. They exercise every
platform route, Back, old buttons, permissions and diagnostic identity without polling live
Telegram or spending AI tokens. Full suite: 146 tests passed; offline evaluation: 39/39.
